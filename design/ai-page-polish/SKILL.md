# AI 页面打磨：从 Demo 到产品

## 触发时机

**仅在用户明确说出"启动AI味检查"时激活本流程。** 日常页面开发迭代中不要自动执行此流程，避免每轮修改都跑全套检查导致效率过低。当你说"优化一下""页面不好看"等普通指令时，按常规方式处理即可。

## 核心理念

AI 生成的页面能运行只是 Demo。Demo 解决"功能能不能运行"，产品解决"用户能不能顺利使用"。
差距集中在四个维度：**对齐、间距、层级、状态**。

**三条铁律：**
1. **先分析后修改** —— 每轮让 AI 先列出问题，确认后再执行，禁止直接改代码
2. **一次只调一个变量** —— 同时改多项则无法定位好坏原因
3. **明确改动边界** —— 每条指令给出检查对象、修改目标、禁止事项

## 执行流程

页面功能跑通后，严格按以下顺序逐轮处理，每轮完成后预览验收再进入下一轮。

```
Task Progress:
- [ ] Step 1: 对齐 — 建立稳定的视觉基准
- [ ] Step 2: 间距 — 让内容关系清晰
- [ ] Step 3: 层级 — 确定用户先看什么、先做什么
- [ ] Step 4: 状态 — 让页面能处理真实情况
- [ ] Step 5: 逐轮验收确认
```

### Step 1: 对齐

**目标：** 统一页面元素的水平/垂直对齐基准线，消除"散乱感"。

**检查清单：**
- 页面标题、说明文字、卡片正文、列表是否共享左侧起点
- 是否存在因嵌套容器导致的无意义缩进偏移
- 按钮、数字、操作区域是否有明确的右侧对齐关系

**指令模板：**
```
检查当前页面的水平对齐关系。
统一页面标题、说明文字、卡片和列表的左侧起点，减少没有必要的嵌套缩进。
检查按钮、数字和操作区域是否存在明确的右侧对齐关系。
只调整对齐，不修改功能、颜色和组件结构。完成后列出具体改动。
```

### Step 2: 间距

**目标：** 收敛间距值到少数几个档位（推荐 8/12/16/24/32），用间距表达内容亲疏关系。

**检查清单：**
- 标题与说明文字是否靠近（同组）
- 表单标签与输入框是否贴近
- 卡片内部边距是否统一
- 卡片之间距离是否大于卡片内边距（不同组拉开）
- 页面不同区块之间是否有足够间距

**指令模板：**
```
检查当前页面的间距系统。
把相近的间距值合并，只保留少量固定档位（如 8/12/16/24/32）。
相关元素靠近，不同模块拉开。
重点检查：
1. 标题与说明文字
2. 表单标签与输入框
3. 卡片内部边距
4. 卡片之间的距离
5. 页面不同区块之间的距离
这次只修改间距，不调整颜色、字号、阴影和功能。
```

### Step 3: 层级

**目标：** 让最重要的信息最显眼，辅助信息退后，建立清晰的视觉优先级。

**先分析，后执行：**
```
先不要修改代码，请分析当前页面：
1. 页面最重要的信息是什么？
2. 用户最应该完成的动作是什么？
3. 哪些内容属于辅助信息？
检查当前的字号、颜色、按钮样式和卡片样式，是否符合这个优先级。
列出存在冲突的地方，并给出修改建议。
```

**判断标准：**
- 一个页面有三个同样醒目的按钮 = 没有主按钮
- 所有卡片都有阴影 = 阴影失去强调作用
- 所有文字都加粗 = 没有重点

确认分析无误后再让 AI 执行修改。

### Step 4: 状态

**目标：** 补齐真实场景下的异常状态处理，消除半成品感。

**必须检查的 9 种状态：**

| 状态 | 典型场景 |
|------|----------|
| 空数据 | 首次打开，列表无内容 |
| 加载中 | 网络请求未返回 |
| 操作成功 | 提交/保存后的反馈 |
| 操作失败 | 接口报错的处理 |
| 按钮禁用 | 表单未填完/条件不满足 |
| 重复提交 | 用户连续点击按钮 |
| 内容过长 | 标题/文本超出设计预期 |
| 图片加载失败 | 网络异常或资源不存在 |
| 移动端窄屏 | 小屏适配 |

**指令模板：**
```
检查当前页面是否完整处理以下状态：
空数据、加载中、操作成功、操作失败、按钮禁用、重复提交、内容过长、图片加载失败和移动端窄屏。
先列出缺失状态及影响，不要直接修改代码。等我确认后，再逐项补齐。
修改时优先复用现有组件，不引入新的状态管理库，不做无关重构。
```

### Step 5: 逐轮验收

每轮结束后要求 AI 汇报：
```
请说明本轮修改了哪些文件、解决了什么问题，以及我应该如何验证。不要继续做下一轮优化。
```

## 常见误区

| 误区 | 正确做法 |
|------|----------|
| 对 AI 说"页面不好看，帮我优化一下" | 拆解为对齐/间距/层级/状态的具体检查项 |
| 四项一起改 | 一次只调一个变量 |
| 让 AI 直接改代码 | 先分析列出问题，确认后再执行 |
| AI 为补一个状态顺手重构半个项目 | 明确"不引入新库、不做无关重构"的边界 |
| 页面变好但不知道哪项起作用 | 每轮只改一项，改完验收 |
